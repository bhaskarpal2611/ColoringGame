# TMKOC PlaySchool - Coloring & Drawing Game (Unity Project)

Welcome to the **ColoringGame** Unity project. This repository contains the interactive coloring, drawing, and path-following minigames designed for the TMKOC PlaySchool application. It is optimized for mobile deployment (Android & iOS) and features dynamic AssetBundle loading, localized audio streaming, and robust offline progress tracking.

---

## 🎮 Project Overview & Architecture

The project consists of three main gameplay modes:
1. **ColorSwipe / Coloring Game (`ColorSwipe_Scene.unity`):** Multi-sprite dynamic texture painting. Players swipe on sprites to paint them using color, pattern texture, or erase brushes.
2. **DrawPaint (`DrawPaint_Scene.unity`):** Canvas-style drawing on customizable templates.
3. **Bezier Path Following / Route tracing (`bezier_follow` logic):** Trailing paths/routes using Bezier curves (e.g. trace-to-identify minigames).

### Technical Stack
* **Unity Version:** `Unity 6 (6000.0.62f1)`
* **Render Pipeline:** Universal Render Pipeline (URP 17.0.4) 2D Renderer
* **Asset Loading:** Dynamic Scene & Category loading via AssetBundles
* **Submodules:** Contains the `PlaySchoolAPI` submodule for backend data sync and student databases.

---

## 🛠️ Key Systems

### 1. Painting Engine (`PaintService.cs` & `PaintController.cs`)
* **Logic:** Raycasts screen touch/drag events onto sprite colliders, translates world coordinates to texture UV coordinates, and uses custom shaders (`Custom/PaintCircleTexture_URP6` etc.) to blit paints/textures onto a temporary `RenderTexture` which is copied back to the sprite's texture.
* **Optimizations (iOS Crash Fix):**
  * Clamped the absolute maximum draw steps to `40 steps per frame` to prevent GPU choking during extremely fast swipe gestures.
  * Commented out per-frame `ReadPixels` calls that saves the colored sprite's state to memory, resolving memory accumulation crashes on older iOS devices.

### 2. Runtime Audio Loader (`RuntimeAudioLoader.cs`)
* **Features:** A persistent singleton that downloads language-specific zip archives on demand from an Amazon Cloudfront CDN:
  `https://d2r38fn3ydtrfq.cloudfront.net/{CategoryName}/{Language}.zip`
* **Workflow:** Downloads the `.zip` archive, extracts it to the local persistent data path (`Application.persistentDataPath/AudioBundles`), loads the `.mp3` files at runtime via UnityWebRequests as `AudioClips`, and caches them.
* **Supported Languages (15+):** English, Tamil, Hindi, Telugu, Malayalam, Bengali, Gujarati, Marathi, Punjabi, Kannada, Odia, Russian, French, Spanish, German.

### 3. Dynamic AssetBundle System (`BundleTestandLoad.cs`)
* **Features:** Unloads unused bundles and asynchronously loads scene bundles from streaming assets at runtime based on the selected category.
* **Student Data display:** Reads stats (attempts, levels completed/total, stars, time spent) from `UpdateCategoryApiManager` to populate UI category selections.

### 4. PlaySchool Data API Submodule (`PlaySchoolAPI`)
* **Location:** Located at `Assets/PlaySchoolAPI` (managed as a Git submodule).
* **Data Flow:** Integrates local gameplay metrics with the offline database using encrypted JSON.
* **Security:** Uses `EncyptedDecryptedData.cs` to encrypt/decrypt student data stored in `.dat` files under the persistent data directory (`StudentName resentGameData.dat`).

```
ColoringGame/
├── Assets/
│   ├── _ColoringGame/                # Core coloring game scene, scripts, SOs, shaders
│   │   ├── Scripts/
│   │   │   ├── Manager/              # SaveManager, AudioManager, PhotoManager
│   │   │   └── PaintingLogic/        # PaintService, PaintController (Core engine)
│   ├── _IdentificationGame/          # Bezier path following utils
│   ├── PlaySchoolAPI/                # Git Submodule for student data tracking
│   ├── Editor/                       # Build tools & shader configuration helper
│   ├── Scenes/                       # Main entrance scene (PlayschoolMainScene.unity)
│   └── StreamingAssets/              # Folder for built AssetBundles
├── ProjectSettings/                  # Unity project configurations
└── *.cs (Root files)                 # Autogenerated SRP RenderGraph CommandBuffers
```

*Note: The CommandBuffer files at the root of the project (`ComputeCommandBuffer.cs`, `RasterCommandBuffer.cs`, `UnsafeCommandBuffer.cs` etc.) are automatically generated by the Scriptable Render Pipeline (SRP) generator and are safe to keep as part of the repository context.*

## ⚙️ Setup & Developer Workflows

### Prerequisites
* Unity Hub with **Unity 6 (6000.0.62f1)** installed.
* Git installed on your local machine.

### 1. Clones & Submodules
Clone the repository recursively to fetch the `PlaySchoolAPI` submodule dependency:
```bash
git clone --recurse-submodules https://github.com/bhaskarpal2611/ColoringGame.git
```
If you cloned the repository normally, fetch the submodules manually:
```bash
git submodule init
git submodule update
```

### 2. Shader Setup (Pink Shaders Fix)
If sprites render as pink/magenta in builds or play mode:
1. Open the project in the Unity Editor.
2. Navigate to the top menu: **Tools > Fix Pink Shaders**.
3. This adds `Universal Render Pipeline/2D/Sprite-Lit-Default` and `Custom/PaintCircleTexture_URP6` to the **Always Included Shaders** array in `ProjectSettings/GraphicsSettings.asset`.

### 3. AssetBundles Build Pipeline
AssetBundles must be compiled for levels to load correctly:
* Navigate to: **Assets > Build AssetBundles > Build All** (or choose Android/Windows specific builds).
* This generates the bundles directly under `Assets/AssetBundles/` and copies them to the respective subfolders under `Assets/StreamingAssets/`.

The project includes the **Graphy Ultimate Stats Monitor** integrated into the development setup to monitor CPU, GPU, FPS, and Mono/GCT memory consumption in real time on target devices. 

Ensure that any changes made to drawing/painting updates are profiled, keeping iOS memory limits in mind to avoid OOM crashes.
